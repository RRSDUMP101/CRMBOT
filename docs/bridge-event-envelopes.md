# Negotiated bridge event envelopes

The existing signed `GET /api/bridge/events` keeps its legacy response by default. The exact optional query `envelope=2` requests a page marked `envelopeVersion: 2`, with the same additive marker on every event. Other envelope values or duplicate query parameters are rejected. HMAC signs the complete URL, including negotiation. This event format is independent of HMAC key-ring authentication v2.

Existing event fields and immutable record JSON are unchanged. Added fields are `sourceSystem: crm`, `aggregateType`, `aggregateId`, `aggregateVersion`, `correlationId`, nullable `causationId`, and `payloadHash`. Aggregate versions count committed events for the same organization/entity/record ID, in source sequence order. Without a known upstream cause, correlation is the event ID and causation is null; the service does not invent lineage. SHA256 hashes the raw record with recursively sorted object keys and unchanged array order/string columns. It is calculated from the retained event on read.

Migration `035_bridge_event_envelopes.sql` adds a side table and index, backfills metadata only and adds an AFTER INSERT trigger so new source events and metadata commit atomically. The trigger counts retained same-aggregate history, including history before the metadata backfill. Metadata is immutable and retained. No customer rows, source events, event IDs or source sequences are rewritten. A missing/inconsistent side-table row fails the negotiated read instead of silently returning an incomplete envelope.

Rollout: apply CRM 035 and native Sale 0020, deploy both consumers/producers, then enable Sale `RRS_CRM_EVENT_ENVELOPE_V2_ENABLED`. Sale requires negotiated envelopes, verifies the record hash, persists a separate metadata digest, and keeps the original base-event receipt hash for historical replay compatibility. Disabling the Sale flag restores legacy reads without deleting metadata or rewinding cursors.

Validation: `tests/bridge-envelope.test.ts` proves metadata-only upgrade and canonical vectors. `tests/chat-bridge.test.ts` covers negotiated API behavior, legacy preservation, concurrent per-aggregate ordinals, rollback and metadata retention. Sale's `tests/crm-event-envelopes.mjs` uses temporary D1 to validate tamper rejection, legacy receipt upgrades, per-aggregate gaps, atomic pages and downgrade prevention.
